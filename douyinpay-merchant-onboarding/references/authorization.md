# 授权与登录流程

## 登录状态检查

```bash
dypay-cli auth status --json
```

发起任意登录或个人入驻授权前必须先执行一次，用于识别当前本地凭证是否已有登录态。

规则：

- 如果已登录，当前返回的 `merchant_id` 是「旧登录商户号」，不一定是本次新入驻商户；
- 发起新入驻后，在执行 `auth login --complete --json` 前，`auth status` 仍会显示旧商户；
- 不得将旧 `merchant_id` 用于本次新入驻后的签约、密钥配置或交接。

返回中可使用的信息包括：

| 字段 | 用途 |
|---|---|
| `logged_in` | 是否有可用登录态 |
| `status` | `valid` / `expired` 等状态 |
| `merchant_id` | 当前商户号 |
| `client_id` | CLI client id |
| `token_type` | token 类型，不含 token 值 |
| `expires_at` | 凭证过期时间 |

禁止读取、打印或要求用户提供 access token。

## 入驻与登录场景

### 已是商家

用户选择「我已经是商家」时，使用默认登录场景：

```bash
dypay-cli auth login --no-wait --json
```

### 个人入驻

用户选择「我要入驻」时，默认按个人主体入驻，先收集并校验：

- 商户简称；
- 联系邮箱。

然后发起个人入驻授权：

```bash
dypay-cli auth login \
  --biz-scene PERSON_REGISTER \
  --biz-extra '{"short_name":"<SHORT_NAME>","email":"<EMAIL>"}' \
  --no-wait \
  --json
```

`PERSON_REGISTER` 设备流会生成用于个人扫码入驻的一次性授权会话。商户简称与联系邮箱只作为本次入驻参数使用，不写入本地状态。

## `--no-wait` 返回字段

`--no-wait --json` 返回类似：

```json
{
  "user_code": "...",
  "verification_uri": "...",
  "expires_in": 7200
}
```

注意：`--no-wait` 只表示待完成授权流程已保存并可继续完成授权，不表示已经登录、入驻成功或已经获得新商户 token。

用户可见输出必须包含：

- `verification_uri`：**完整展示**授权链接，不得截断；
- `user_code`：页面上核对的确认码；
- 有效期：将 CLI 返回的 `expires_in` 换算为分钟展示，向上取整，不向用户展示秒数；
- 安全提示：确认页面展示的确认码与 CLI 返回一致；
- 状态提示：扫码完成后还必须用户确认完成授权后，才能执行完成命令，否则本地仍是旧登录态。

示例输出格式：

```text
📱 请打开授权链接并使用抖音 APP 扫码完成授权

授权链接: <CLI 返回的 verification_uri>
确认码: XKRX-JJNB
有效期: 120 分钟

请确认页面上的确认码与上方一致。
```

不要手动改写、补全或拼接 `verification_uri`，必须原样完整输出。有效期不向用户展示秒，换算成分钟数

## 授权完成后换取登录态

用户明确表示已完成扫码/授权/签约后，必须执行 CLI 返回的完成命令：

```bash
dypay-cli auth login --complete --json
```

规则：

- 只执行一次；
- 不在用户确认前轮询；
- 如果返回授权未完成，提示用户完成页面操作后再重试；
- 如果授权二维码过期，重新发起 `--no-wait`；
- 成功后立即执行 `dypay-cli auth status --json` 验证 merchant_id；
- 若换取结果中的 `merchant_id` 与 `auth status` 不一致，或 `auth status` 仍为授权前旧商户号，必须停止流程并排查，不得继续签约。

## 授权等待超时控制

用户扫码授权是异步操作，必须设定超时上限，避免无限等待：

- **等待用户确认授权的超时**：从展示授权链接后开始计时，最多等待 **N 分钟**；N 以 CLI 返回的 `expires_in` 换算后的分钟数为准；
- 超时后动作：
  1. 提示用户：「授权二维码已过期」；
  2. 询问用户：「是否重新发起授权？」；
  3. 若用户选择重新授权，重新执行 `auth login --no-wait --json`；
  4. 若用户选择退出，记录当前进度为断点并结束流程；
- 不要在用户未确认的情况下自动轮询完成命令；

### 有效期展示规则

- CLI 返回的 `expires_in` 是原始有效期数值，单位是秒，对客展示必须统一转换为分钟；
- 分钟数向上取整，例如 `expires_in=7199` 展示为「 120 分钟」；
- 不向用户展示原始数值或秒数表达；
- 对客过期文案统一使用「授权二维码已过期」；
- 不向用户展示内部实现词。

## 常见授权异常

| 异常 | 处理 |
|---|---|
| 授权二维码过期 | 重新执行 `auth login --no-wait --json` |
| 用户未完成授权 | 等待用户完成，不自动轮询 |
| 用户拒绝授权 | 停止流程，询问是否重新授权 |
| 凭证过期 | 提示重新登录；必要时先 `auth logout --json` |
| merchant_id 为空 | 说明授权未形成可用商户登录态，回到入驻/登录确认 |
| 网络超时 | 提示稍后重试或检查网络环境 |
