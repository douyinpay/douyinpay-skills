# 异常处理矩阵

本文件定义入驻 Skill 的失败识别与恢复路径。原则：所有失败都要给出明确下一步，不输出模糊的“请重试”。

## CLI 与环境错误

| 异常 | 识别信号 | 处理                                       |
|---|---|------------------------------------------|
| CLI 未安装 | `dypay-cli: command not found` | 参考 `references/cli-commands.md` 进行安装 |
| CLI 命令拼写错误 | 返回 unknown command/flag | 对照 `references/cli-commands.md` 修正，不自行猜测 |
| 网络超时 | timeout / connection refused | 提示检查网络，稍后重试                             |
| 平台检测失败 | `check_credential.py --json` 返回 `status=error` 或 `reason=check_failed/unauthorized` | 按照未检测到平台集成处理，继续执行 CLI 安装和商户登录态检查 |
| CLI 未登录或登录态过期 | `dypay-cli auth status --json` 返回 `logged_in=false` 或 `status=expired` | 引导用户选择入驻或已有商家登录路径，不直接进入签约或支付集成          |

## 入驻信息错误

| 异常 | 识别信号 | 处理 |
|---|---|---|
| 邮箱格式不合法 | 本地校验失败 | 要求用户重新输入联系邮箱 |
| 商户简称本地规则不合法 | 空/纯空白、超过 30 个字符、含非中文英文数字字符、前后含空白、包含“支付” | 要求用户重新输入商户简称；不调用接口、不进入授权 |
| 商户简称不通过 | `checkshortName` 返回 `pass=false` | 展示返回原因（如有），要求更换简称 |
| 商户简称接口失败 | CLI 返回业务错误/网络错误 | 保留当前输入，不进入授权；提示重试校验 |

## 个人扫码入驻异常

| 异常 | 触发条件 | 用户提示                      |
|---|---|---------------------------|
| 授权二维码过期 | 授权二维码超过有效期 | 重新生成入驻授权链接/二维码            |
| 误用登录二维码 | 后端提示 scene 不匹配 | “该二维码不能用于入驻签约，请扫描当前入驻二维码” |
| 未实名 | 抖音账号未完成实名认证 | 引导至抖音 App 完成实名认证后重试       |
| 身份证照片缺失 | 实名通过但影像件缺失 | 引导在抖音 App 补充身份证照片后重试      |
| 未绑储蓄卡 | 无储蓄卡 | 非阻塞；提示入驻后去商家平台绑定储蓄卡提现     |
| 仅绑信用卡 | 无可用储蓄卡 | 非阻塞；提示信用卡不可用于提现，后续补绑储蓄卡   |
| 签约失败 | 个人入驻签约接口失败 | 允许重试；多次失败提示联系支持           |

## 授权登录异常

| 异常 | 处理 |
|---|---|
| 用户未完成授权 | 等待用户完成，不自动轮询 |
| 用户拒绝授权 | 停止流程，询问是否重新授权 |
| 换取登录态失败 | 展示错误摘要，必要时重新生成授权二维码 |
| 登录成功但 `merchant_id` 为空 | 说明未形成可用商户态，回到入驻/登录确认 |
| `--no-wait` 后直接 `auth status` 仍显示旧商户 | 这是预期行为；说明尚未执行 `--complete` 换取新 token，必须先完成授权 |
| 完成授权后仍显示旧 `merchant_id` | 停止签约和密钥配置；核对是否使用了本次授权流程、授权二维码是否过期、用户是否完成扫码确认 |
| `auth login --complete` 无待完成授权状态 | 重新执行 `auth login --no-wait --json` 发起新的授权流程 |
| 凭证过期 | 提示重新登录；用户同意后可 `auth logout --json` 再登录 |

## 文件上传异常

| 异常 | 处理 |
|---|---|
| 文件不存在 | 要求用户提供正确路径 |
| 文件格式不支持 | 要求 JPG/PNG 等图片格式 |
| 上传需要登录 | 先执行授权登录 |
| 返回无 `file_url` | 输出返回摘要并停止，不自行构造 URL |
| 截图不清晰 | 要求重新截图，说明首页/销售页要求 |

## 签约状态分流

`dypay-cli sign query-by-code --product-code CO_PAY_NATIVE --json` 返回的状态按以下方式处理：

| 内部状态 | 用户展示状态 | 处理 |
|---|---|---|
| `available` | 已签约 | 跳过签约，进入密钥配置 |
| `init` | 申请中 | 不重复提交；视为签约申请已提交，可继续推进证书密钥配置和后续支付集成 |
| `wait_signing` | 签约处理中 | 不重复提交；视为签约申请已提交，可继续推进证书密钥配置和后续支付集成 |
| `wait_auditing` | 审核中 | 不重复提交；视为签约申请已提交，可继续推进证书密钥配置和后续支付集成 |
| `rejected` | 已驳回 | 展示原因，按截图/业务原因修复后再由用户确认重提 |
| `failed` | 签约失败 | 展示原因，确认后可重试 |
| `terminated` | 已终止 | 说明当前合约已终止，需业务确认后重新签约 |
| `unavailable` | 未签约 | 进入材料上传和签约 |
| 空结果/无 profile | 未签约 | 进入材料上传和签约 |

对用户输出时必须使用「用户展示状态」列，不得直接展示内部状态英文枚举。

## 签约提交异常

| 异常 | 处理 |
|---|---|
| 用户要求签约非 Native 支付产品 | 不执行 CLI 签约；说明当前 Skill 产品签约只支持 Native 支付，引导用户前往抖音支付商家平台【产品中心】自行开通/签约对应产品 |
| 重复申请 | 返回当前申请状态，不重复提交 |
| 缺少 `--web-info` | 停止提交，按 CLI 格式补充 `--web-info '{"home_page_pics":[...],"service_pics":[...]}'` |
| `web-info` JSON 无效 | 修正 JSON 字符串，确保双引号和数组格式合法 |
| `home_page_pics` 为空 | 重新上传域名首页截图，并使用返回的 `file_url` |
| `service_pics` 为空 | 重新上传销售/服务页截图，并使用返回的 `file_url` |
| 截图质量不合格 | 说明哪张截图不合格，引导重新上传 |
| 截图内容不匹配 | 说明截图需包含首页、商品/服务、价格或交易入口 |

## 密钥配置异常

| 异常 | 处理 |
|---|---|
| 用户粘贴私钥/接口加密密钥 | 立即停止，提醒视为泄露并轮换 |
| 商家平台证书密钥配置未完成 | 引导用户回到抖音支付商家平台【产品中心】→【开发者配置】→【密钥管理】完成配置 |
| 未下载私钥 | 若仍在快捷引导中，先下载私钥；若已无法找回，按商家平台流程重新生成/轮换证书 |
| 私钥格式错误 | 引导重新在商家平台生成 |
| 接口加密密钥为空 | 引导回【产品中心】→【开发者配置】→【密钥管理】→ 接口加密密钥 → 查看 |
| 接口加密密钥格式错误 | 引导检查密钥串完整性并重新提交 |
| 忘记下载商户 API 证书 | 引导在密钥管理左侧证书列表重新下载 |
| 忘记下载平台公钥证书 | 引导在左侧「抖音支付公钥证书（RSA）」列表重新下载 |
| 年度证书申请次数接近上限 | 避免反复重新生成，按官方证书更换/作废流程处理 |

## 生产集成异常

| 异常 | 处理 |
|---|---|
| `douyinpay-payment-integration` 不可用 | 停止自动推进，提示用户启用或安装后继续 |
| 商家平台证书密钥配置未完成 | 阻断支付集成，回到证书密钥配置 |
| 签约审核中 | 输出当前状态，提示不要重复提交；如商家平台证书密钥配置已完成，可继续调用支付集成 Skill |
| 用户要求直接改代码 | 拒绝直接修改，提供配置指引 |
